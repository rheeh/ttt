# 方案评估与实施路线

## 结论

原方案产品边界正确，但一期同时覆盖数据源、选股、复盘、报告、三种导出、React 和 Electron，难以为每条业务规则建立可验收证据。开发改为“独立仓库 + 纵向切片”：每一阶段都必须有界面、API、持久化和测试闭环。

## 已核对的风险

1. `meirixuangu.skill` 的实际打分不只是文档所述的“五维”，还包含量价、均线、换手、振幅、板块动量和运行时段微调。第一版评分引擎按实际脚本语义分维度移植，不用文档摘要猜测。
2. 免费网页行情接口可能限流或改字段，不能成为核心测试的前置条件。数据采集将通过适配器接入，评分引擎只接收标准化事实。
3. 原备份中存在明文 Key 风险；原文件保留在项目仓库外，不复制、不提交。
4. “梭哈区”等是个人标签，数据模型可保留，但界面始终与自动交易能力隔离。
5. 手机与电脑各自本地存储，共享的只能是 JSON Schema、规则文档和固定测试向量。固定股票池只是参考数据，不作为个股查询准入条件。

### 已取消的范围

- 条件选股：取消独立入口，股票查询统一使用全市场搜索与用户自建自选池；
- 达人消息：取消 M3 规划，不在当前个人本地研究工具中维护消息推送链路；
- 手机端：暂不排期，先完成桌面端数据可信度、图形分析、研究日志、核验统计和备份导出。

## 验收原则

- AI 和网络关闭后，本地历史与评分仍可用；
- 任何候选都能追溯策略版本、输入、各维度得分和时间；
- 评分同时记录策略文件与评分代码的规则指纹；
- 数据缺失明示，不伪造占位；
- 没有券商接口或任何自动下单路径。
