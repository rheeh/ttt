# 方案评估与实施路线

## 结论

原方案产品边界正确，但一期同时覆盖数据源、选股、复盘、报告、三种导出、React 和 Electron，难以为每条业务规则建立可验收证据。开发改为“独立仓库 + 纵向切片”：每一阶段都必须有界面、API、持久化和测试闭环。

## 已核对的风险

1. `meirixuangu.skill` 的实际打分不只是文档所述的“五维”，还包含量价、均线、换手、振幅、板块动量和运行时段微调。第一版评分引擎按实际脚本语义分维度移植，不用文档摘要猜测。
2. 免费网页行情接口可能限流或改字段，不能成为核心测试的前置条件。数据采集将通过适配器接入，评分引擎只接收标准化事实。
3. 原备份中存在明文 Key 风险；原文件保留在项目仓库外，不复制、不提交。
4. “梭哈区”等是个人标签，数据模型可保留，但界面始终与自动交易能力隔离。
5. 手机与电脑各自本地存储，共享的只能是 JSON Schema、规则文档和固定测试向量。

## 分期

### M0（当前）：可运行研究闭环

- 原创 React 工作台；
- 本地 FastAPI + SQLite；
- 策略 JSON Schema 与“群友原版 v1”；
- 评分试算、评分解释、预选股保存和状态更新；
- 离线自动测试。

### M1：真实数据与复盘

- [x] 腾讯实时行情适配器；
- [x] 来源、抓取时间、交易时间和降级状态；
- [x] 固定池批量扫描与 SQLite 行情快照；
- [ ] AKShare 日线适配器与 MA5/10/20；
- [ ] 每日预选和盘后快照；
- 预选股 1/5/20 日核验。

### M2：深度报告与桌面封装

- K 线和技术指标；
- 亮色个股报告，HTML/PDF 导出；
- Electron 打包，后端仍只监听回环地址；
- 本地备份与恢复。

### M3：手机与达人消息

- Flutter/Android 独立数据库；
- RSS/API 优先的达人适配器；
- 去重、股票识别、本地通知和一键加入预选；
- 是否使用轻量推送中继，在给出达人名单后决定。

## 验收原则

- AI 和网络关闭后，本地历史与评分仍可用；
- 任何候选都能追溯策略版本、输入、各维度得分和时间；
- 数据缺失明示，不伪造占位；
- 没有券商接口或任何自动下单路径。
