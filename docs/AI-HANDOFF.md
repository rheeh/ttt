## 1. 项目背景和最终目标

本项目是一个独立开发、仅限个人使用的 A 股研究工具。目标是让用户：

1. 搜索任意 A 股或 ETF；
2. 获取行情、前复权日线和可用的增强数据；
3. 生成可解释的个股技术/基本面/资金/行业诊断；
4. 保存自选、研究报告、扫描快照和候选表现；
5. 用历史数据复盘评分规则，而不是把软件分数当作交易指令。

项目明确不连接券商、不下单、不提供委托、撤单或自动交易路径。数据默认保存在本机 SQLite，API 只监听 `127.0.0.1`。

“群友原版”固定池只保留为可选参考池和策略扫描样本，不是全市场查询限制，也不能被描述为全市场统计。

## 5. 已确定的方案、决策和原因

1. **参考池和全 A 分离。** 固定池是策略样本，不是市场数据库；因此复盘页面必须带 `scope=reference_pool` 和池元数据。
2. **健康度不使用策略评分。** 上涨率、平均涨跌、覆盖率等只从行情状态和涨跌字段计算；`top_scores`、`strategy_average_score` 只能作为策略摘要。
3. **数据缺失不伪造。** 不能用 `0` 或静态硬编码冒充实时资金流、行业热度或全 A 统计。
4. **腾讯资金扩展只能标为降级源。** `p[68]/p[70]/p[71]` 是非正式扩展字段，必须显示来源和“估算/非五档”口径，不能直接写成东方财富资金流。
5. **行业降级只做可解释计算。** 本地映射仅用于分组，板块平均涨跌、上涨/下跌家数和领涨股来自成分行情；主力资金不从普通行情推导。
6. **先桌面可信度，再移动端/消息。** 数据结构、快照、核验和复盘稳定前不开发 Flutter、达人消息或推送。
7. **独立 GitHub 提交。** 目标仓库是 `rheeh/ttt`，不要关联或合并到其他项目；可以参考代码但不直接照搬外部项目的硬编码和外部依赖。

## 8. 未解决的问题和风险

1. **全 A 交易日缺口。** `stock_zh_a_spot_em` 可返回现货行，但不可靠提供权威交易日；必须补全 A 日线/交易日源后才能把快照状态提升为完整。
2. **数据源必须按接口标注。** 板块雷达已切换到新浪行业接口；AKShare 的其他接口仍可能访问东方财富，不能把“安装 AKShare”笼统等同于某个数据源可用。
3. **行业池外覆盖不足。** 本地行业降级计算依赖 66 股参考池映射，用户搜索的池外股票可能仍没有行业名称/横截面。
4. **参考池扫描仍是策略扫描。** `MarketScanner` 仍使用固定参考池、策略文件和部分缺失字段默认行为；不能把扫描结果写成全市场排名。
5. **全 A 快照未持久化。** 当前接口是即时返回，没有历史日期切换、自动盘后保存和趋势比较。
6. **旧兼容字段。** `breadth_pct`、`average_score` 等字段仍保留兼容；后续应在 API 版本或迁移中明确弃用，前端不要再用旧名称表达全市场健康度。
7. **外部接口字段可能变化。** 腾讯扩展字段属于非正式协议，字段位置和单位需要持续冒烟验证；任何单位改变都必须修改测试和页面口径。
