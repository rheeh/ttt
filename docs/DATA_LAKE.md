# 本地数据湖

数据湖用于将采集到的历史长期留在自己的电脑上。它通过 CNEquity 0.11.0 采集和管理 Parquet，SQLite 继续保存自选、报告、训练记录和任务状态。注册数据集是软件内部登记，不需要向作者付费注册；这里运行的是自己的采集后端，不连接作者私有数据仓库。

## 开始使用

在项目根目录运行 `.venv/bin/python -m pip install -r requirements-data.txt`，重启 API，然后打开“数据源状态 → 长期历史数据湖”。输入带市场后缀的代码，例如 `600519.SH, 000001.SZ`，也支持 `sh600519`。最多200只，默认5只示例股票，可替换成自己的研究范围。

- **更新历史数据**：首次补最近1100个自然日；已有日线时重采末尾7天，合并修订并保留更早历史。
- **回补最近3年**：重新采集1100个自然日窗口；可通过 API 将 `history_days` 设为30至3650。
- **采集财报、公告与行业**：按股票范围采集最近740天财务报告，采集最近7天全市场公告索引和近一年全市场申万行业成员历史。
- **应用运行时自动更新**：首次手动采集后，16:20起检查是否缺少最新完成交易日；启用过研究采集后，公告按自然日更新，财报与行业每7天更新。任务串行运行，每类每天最多3次，失败至少间隔15分钟。关闭 API 后停止调度，重新打开后补采。

采集步骤与错误显示在页面，成功发布的数据不因后续步骤失败而删除。任务运行在独立子进程，同一个业务数据库只允许一个活跃任务；超过30分钟终止，缩小范围后可继续补采。仅打开页面不会启动首次采集。默认范围是小规模入门配置，不表示全市场已建库。

## 数据与消费方式

| 数据集 | 保存内容 | 当前如何使用 |
| --- | --- | --- |
| `instruments` | 证券名录 | 采集元数据；首次建库时获取 |
| `trading_calendar` | CNEquity 交易日历 | 保存供查询；应用调度仍以经核对的本地交易所日历为准 |
| `daily_bars` | 所选股票原始日线 | 扫描、个股研究、行业成分计算、训练优先读取 |
| `index_bars` | 上游支持的基准指数日线 | 上证指数与沪深300价格基准 |
| `adj_factors` | 独立后复权因子序列 | 查询时生成前复权价格，不覆盖原始价 |
| `financial_statement_items` | 所选股票财报长表 | 深研财务优先读取，超过7天未采集则尝试在线源 |
| `announcement_index` | 全市场公告标题、日期及链接索引 | 本地保留、API 查询；不自动下载公告全文，不替换现有新闻页 |
| `industry_members` | 申万行业成员历史 | 本地保留、API 查询；尚未替换现有新浪行业雷达的分类及当前成分回推逻辑 |

盘中现价仍由腾讯行情请求。日线优先使用本地完整前复权序列；缺失、因子不足或日期落后时使用腾讯整段前复权窗口，记录回退原因，不把备用源前复权价格混入原始数据湖。个股成交量统一为股；指数成交量保留来源原生单位，不参与个股量能合计。训练允许复用较早的完整历史，继续执行隐藏未来与排除当日行情的规则。

## 保存与复用

默认位置为应用数据目录下的 `cnequity/`；macOS 为 `~/Library/Application Support/ZhixingStockResearch/cnequity/`。页面显示实际路径。可用 `STOCK_RESEARCH_LAKE_DIR` 单独设置数据湖位置，业务数据库仍由 `STOCK_RESEARCH_DATA_DIR` 控制。

```text
cnequity/
  raw/        上游采集产物（取决于适配器）
  staging/    待合并批次
  curated/    已发布的原始历史与研究数据
  derived/    复权因子等派生数据
  meta/       数据契约、采集状态、版本与指针
  logs/       本应用每次采集的日志
```

重复采集按主键合并，同一天的修订更新当前版本，早期日期继续保留。每次任务结束仅保留最近5个数据集版本副本，**不是只保留5天历史**；当前版本保留全部已采集历史。报告内记录实际输入和摘要，旧版本指针在清理后未必还能回放。需要长期审计某一旧版本时，应在清理前另存完整数据湖备份。

页面现有“数据库备份”只备份 SQLite。备份数据湖应先等待采集结束并关闭 API，再复制整个 `cnequity/` 目录（包括 `meta/`），同时保留 SQLite 备份。不要只复制某个 Parquet 分区后声称完整恢复。数据与日志不提交 GitHub。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/data-lake/status` | 依赖版本、覆盖、设置和最近任务 |
| `PUT /api/data-lake/settings` | 保存 `symbols` 与 `auto_update` |
| `POST /api/data-lake/collect` | 提交 `mode`：`update`、`backfill`、`research` 或仅公告 `events`；返回202 |
| `GET /api/data-lake/records/{dataset}` | 读取上表白名单数据集；可选 `code`、`start`、`end`、`as_of`、`limit`（最多1000条） |

例如 `/api/data-lake/records/financial_statement_items?code=sh600519&as_of=2026-08-31&limit=100`。财报与公告查询使用 `best_effort` 时点过滤并保留返回记录的质量标记，不能据此认定严格历史时点可得性。

## 边界

历史日线和财报可反复复用，但后续更正、公司行动和新增报告仍需更新。首次采集以前的公告仅覆盖请求窗口，长期停用后超过7天的公告缺口不会由默认任务自动补齐；可使用 CNEquity 专门回填后再通过本接口读取。名录目前只在首次建库采集，未实现退市股票的完整历史研究池。

本地应用交易日历目前核对至2026年，超出范围会暂停自动采集，不直接把上游未来日历当成已核对事实。财务历史保守标记为 `reconstructed`，不能消除报告修订和来源追溯不足带来的未来信息风险。行业成员已保存不代表现有雷达已迁移为历史时点成分回测。

CNEquity 是 Apache-2.0 代码依赖；上游数据条款仍独立适用。个人本地研究接入不代表获得对外数据 API、原始数据公开发布或商业再分发授权。参见[数据来源与限制](DATA_SOURCES.md)。
