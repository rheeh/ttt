# 数据源与降级语义

## 腾讯行情

当前适配器为 `tencent-qt`，批量请求 `qt.gtimg.cn`。解析后的标准字段包括：

板块雷达使用 AKShare 的新浪行业接口（`stock_sector_spot` / `stock_sector_detail`）获取当前分类、成分映射和当日状态，不使用东方财富板块节点作为核心历史源。后台优先复用 CNEquity 本地历史、缺失时用腾讯前复权成分股日线构造透明的“等权成分指数”：指数日期轴来自真实成分股交易日，板块收盘、5/20/60 日收益、MA20/MA60 宽度、新高比例和量能均从同一批成分数据计算。它明确标记为 `derived-equal-weighted-constituents`，不冒充官方行业指数。后台请求 150 根日线，并要求至少 120 个共同交易日、至少 5 只有效成分。历史覆盖率以原始成分名单与上游声明家数的较大值为分母；不足 80%、历史未更新到预期交易日或日历未知时，不确认阶段。该序列按当前成分回推，标记为 `current_constituents_reconstruction`，不是历史时点成分指数。

板块雷达在已知交易日 16:10 后由本地 API 进程后台刷新。运行日期、失败原因与尝试次数保存在 SQLite，进程重启后恢复；自动更新每天最多尝试 3 次，失败后分别至少等待 5、10 分钟。手动回填可以显式重试，同一进程不并行执行两个回填。上游全失败时保留旧快照并记录失败；部分失败时保存可用结果和缺失提示，缺失部分进入后续补采。应用关闭时后台任务不运行。页面 GET 默认只读取 SQLite；显式“更新全量数据”只刷新当前快照，昂贵的 120 日回填由后台任务或“回填120日历史”触发。阶段信号只在阶段首次满足连续 2 日确认时写入 `industry_signals`，信号核验从该信号后的下一交易日作为基准，并区分改善/转弱方向；MFE/MAE 在方向坐标系中计算。可通过 `/api/market/industry-radar/signals/verify` 核验 1/5/20/60 个交易日收益、沪深 300 超额收益、MFE 和 MAE。样本不足时结果为待核验，不展示有效率。

- 股票代码和数据源当前名称；
- 现价、昨收、今开、最高和最低；
- 涨跌幅、换手率、振幅、成交量和成交额；
- PE、PB；
- 行情交易时间和本机抓取时间。

腾讯当前返回的时间按 `Asia/Shanghai` 解析，不会伪装为 UTC。服务端名称优先于预置名称，因此公司更名后界面可以显示新名称，代码仍保持稳定。

## 历史日线与腾讯备用源

统一历史入口优先读取 CNEquity 数据湖；数据缺失、复权因子不完整或最新日期不符合交易日历时，回退腾讯前复权窗口并记录原因。扫描为每只股票读取最近 30 条前复权日线，至少有 20 条有效收盘价时计算 MA5、MA10 和 MA20。66 只固定股票通过有限并发获取，单只日线失败不会拖垮整次扫描。

个股深研通过统一入口读取最近 252 条前复权日线，计算 MA5/10/20/60、MACD、RSI14、20 日支撑压力、52 周高低点和近 5 日量比。深研财务优先读取采集后7天内的本地财务历史，缺失或过期时回退东方财富最新报告；资金流、行业涨幅横截面和相关新闻仍请求既有接口。四类结果都会携带 `source`、`fetched_at`、`status` 和错误原因，并保存到分析快照。

知行指数会在上述事实之上计算十个可解释因子，并始终按十个因子平均为 0–100 分；不可用因子按中性 50 计入，同时输出 `factor_coverage` 和 `zhixing_confidence`，避免数据源偶发失败改变分母。相对强度使用 `sh000001` 的 20 日收益作基准，周线由日线按 ISO 周聚合。参考池只作为个人偏好加分，不限制全市场查询。每份报告还保存算法版本和规则指纹，以及日线与基准输入的 SHA-256、数据契约版本、来源、覆盖窗口和实际复权口径。摘要对应报告内保存的行情，不是独立历史版本库。

## AKShare 可选备用源

`requirements-optional.txt` 提供 AKShare 安装入口。默认仍优先使用腾讯；当最新价、涨跌幅、PE/PB 等核心字段缺失，或前复权日线请求失败时，才调用 AKShare 东方财富现货/日线接口。AKShare 不可用时不会阻塞主流程，报告和扫描继续按原有降级语义返回。

## 数据状态

- `ok`：当前消费方所需字段完整；
- `degraded`：有真实行情，但某些增强字段缺失；
- `stale`：本次请求失败，使用 SQLite 最近一次成功快照，并显示数据年龄；
- `error`：没有可用的最新价或数据源请求失败。

报告拆分为核心行情状态、增强数据状态和旧版火箭评分状态。全池扫描依赖腾讯实时行情及统一日线入口；资金流、财务、行业和新闻属于个股深研扩展源，不会拖慢或改变全池扫描。增强源请求会自动重试一次，成功结果写入 `analysis_source_cache`；失败时优先回退到最近成功快照，不使用默认值填充。

桌面端“数据源状态”页通过 `/api/health/sources/test` 记录每个源的安装状态、接口可访问性、数据有效性、响应耗时、错误原因和最近成功时间。增强数据失败时使用最近成功快照；行情扫描仍保存每次有效快照供历史复盘，并在结果中记录实际源和回退原因。

## 缓存

每次扫描会按“股票代码 + 数据源 + 交易时间”写入 SQLite，并保存一份扫描运行记录及逐只结果。重复扫描同一行情时更新抓取时间和载荷，不重复堆积记录。板块雷达还保存板块主表、成分有效期、每日指数与宽度、阶段变化及核验结果。个股报告从最近一次 SQLite 雷达快照读取行业阶段、排名、交易日和个股相对行业强度；快照不存在时明确显示待回填。板块自选提醒只对阶段变化触发；`/api/market/industry-radar/export` 可导出 CSV/JSON，`/api/backup` 生成 SQLite 在线备份，不包含独立的 Parquet 数据湖；数据湖备份方法见[数据湖说明](DATA_LAKE.md)。


## 日线校验与交易日历

扫描、个股深研、行业成分历史和训练的腾讯入口使用共同日线校验。股票和 ETF 必须返回显式 `qfqday`，缺失时拒绝以未复权 `day` 替代；上证指数与沪深300作为明确的指数白名单使用原始指数点位。检查日期严格递增、有限正价格、OHLC关系和非负成交量，零成交量保留。坏行使该股票本次日线请求失败，保留原因；不靠跳过坏行拼出成功序列。AKShare前复权日线也使用相同的行校验。

所有日期边界使用上海时区。收盘指标在15:10之前排除当日日线，训练另保留“不使用本机当日行情”的题库规则。深研按预期已完成交易日判断新鲜度，日期不符会注明可能停牌或数据滞后；旧日线可查看，但操作参考保持观望，不输出价格区间。

本地日历目前覆盖2025—2026年，依据[上交所2025年休市通知](https://www.sse.com.cn/disclosure/announcement/general/c/c_20241223_10767108.shtml)和[2026年休市通知](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)。周末调休工作日仍休市。超出覆盖范围时返回未知，暂停自动行业刷新，并提示更新日历；不把所有工作日假定为交易日。此日历用于新鲜度与行业后台调度，候选模块已有的工作日预估到期日期尚未迁移，实际核验仍需看观测到的行情。

CNEquity 已接入独立原始价与复权因子库，本地日线查询固定两个数据集的版本并要求因子精确覆盖；备用腾讯数据仍是上游当前锚点前复权整段窗口。报告保存实际版本、复权锚点、成交量单位与回退原因。个股成交量统一为股，指数保留各源原生单位，仅用于价格基准，不与个股成交量合计。财务优先读取已采集的版本历史，标记 `history_semantics=versioned_financial_statements`、`pit_quality=reconstructed`；备用最新报告仍标记 `latest_snapshot` / `snapshot_only`。这些能力均不等同于严格的历史时点回测。

## 可恢复的行业历史采集

`constituent_history_cache`保存成功的整段前复权窗口，`constituent_fetch_receipts`保存逐股票的请求结果和错误。只有契约版本一致、内容摘要一致、覆盖到最近完成交易日且长度足够的缓存才复用；重跑优先复用成功项，缺失或过期项重新采集。新窗口整段替换，避免将不同前复权锚点的数据直接追加混合。缓存只保留当前窗口，不提供跨版本查询。

`background_task_state`保存后台运行状态；`/api/market/industry-radar/tasks`及页面“数据状态与维护”显示最近成功时间、错误、尝试次数和日历状态。

## CNEquity与数据使用边界

本项目借鉴[CNEquity](https://github.com/rootSunc/CNEquity)的数据契约、失败记录和覆盖校验思路，现在提供可选的 CNEquity 0.11.0 依赖，接入8类数据集及本地采集任务，详见[数据湖说明](DATA_LAKE.md)。未启用的其他数据集不在本项目采集范围内。其“注册数据集”指软件内部数据表登记，不是收费注册服务；仓库不附带作者的生产数据湖，需要使用者自行采集。

CNEquity代码采用Apache-2.0，但该许可不授予其上游行情、公告、财报的再分发或商用权。将采集能力接入个人研究项目仍需遵守对应来源条款；对外数据API、公开托管原始数据或商业使用需逐源核对授权。参见[项目许可说明](https://github.com/rootSunc/CNEquity/blob/main/docs/legal-and-data-sources.md)及[来源登记](https://github.com/rootSunc/CNEquity/blob/main/sources/SOURCES.yml)。
